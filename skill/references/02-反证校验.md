# 卷二·反证校验

> 兼听则明，偏信则暗。——《资治通鉴》<br>
> 凡治众如治寡，分数是也。——《孙子兵法》

## 人性原理

人天然喜欢顺着已有结论往下走。先有判断，再找证据；先有立场，再补理由。臣子若知道君主想听什么，最省力的做法不是查明真相，而是替君主把话说圆。

AI 同理。模型会倾向于完成你的预设，而不是审判你的预设。你问"为什么这个方案可行"，它就会找可行的理由；你问"如何实现这个功能"，它就会默认功能值得实现。若不主动设立反证机制，AI 很容易成为一名能言善辩的佞臣。

反证校验的核心，不是让 AI 永远唱反调，而是让它在关键结论之前先过三关：
- 是否存在反例？
- 证据是否足够？
- 若判断错误，代价是什么？

## 反证校验·三段话术

### 一、先立敌论

**判定标准**：你已经有一个初步方案，但担心模型顺着你的意思附和。

**话术模板**：
```
我的初步判断是：{你的判断或方案}。

在继续完善之前，先不要支持它。
请你站在反方立场，列出最可能推翻这个判断的 3 个理由。

每个理由必须包含：
- 它攻击的是哪个前提
- 需要什么证据才能确认
- 如果它成立，原方案应如何调整

只有在反方理由处理完之后，才允许进入优化方案。
```

**帝王术注解**：这是御前设谏官。忠臣不是凡事点头，而是在君主将错未错之时先拦一道。若无人敢逆耳，朝堂越和气，败亡越近。

---

### 二、证据分账

**判定标准**：模型给出了结论，但结论中混杂事实、推断和猜测。

**话术模板**：
```
请把你的结论拆成三类：

1. 已确认事实：有明确来源、代码、日志、数据或上下文支持
2. 合理推断：由事实推出，但仍可能有其他解释
3. 待验证假设：目前只是猜测，不能当作依据

然后给出：
- 哪些结论可以立即采用
- 哪些结论需要验证后才能采用
- 若时间有限，最应该先验证哪一项

不要把推断写成事实。
不要用流畅语气掩盖不确定性。
```

**帝王术注解**：这是户部清账。粮草、军饷、欠款，各归各账；事实、推断、猜测，也必须各归各账。账目混了，贪官与庸官都有藏身之处。

---

### 三、败局预演

**判定标准**：方案即将执行，错误代价较高，或会影响用户、资金、安全、数据、生产环境。

**话术模板**：
```
假设这个方案已经失败。

请倒推它最可能失败的 5 条路径，并按风险排序。
每条路径说明：
- 触发条件
- 早期信号
- 可提前布置的防线
- 失败后最小损失的回滚方式

最后给出一个停机条件：
出现什么信号时，必须停止执行，不得继续硬推。
```

**帝王术注解**：这是未战先算败。将军只讲胜法，便是邀功；能讲败法，才是可托兵权。真正的稳，不是相信必胜，而是败也不至溃。

## 使用要诀

- **越关键，越先反证**：小事可以快，大事必须慢。凡涉生产、法务、财务、安全、公开发布，先问反例，再问执行。
- **反证不是抬杠**：反证必须攻击前提、证据或代价，不能只说"也许不行"。
- **证据要分层**：事实可以落锤，推断只能暂用，假设必须标记。三者混用，是幻觉的温床。
- **设停机条件**：没有停机条件的计划，本质上是在赌模型不会错。

## 模型适配

此策略适用于所有模型，但授权强度不同。

- **L1 模型**：只允许按清单列反例和待验证项，不允许自行裁决。
- **L2 模型**：可以给出风险排序，但必须说明排序依据。
- **L3 模型**：可以主动提出替代方案，并指出用户原始目标是否需要重写。

反证校验尤其适合用于代码改动、技术选型、PR review、上线前检查、法律或财务相关判断。若任务涉及最新版本、价格、政策、榜单或新闻，应先执行联网核验，再做反证校验。
