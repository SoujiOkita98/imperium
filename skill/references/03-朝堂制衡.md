# 卷三·朝堂制衡

> 兼听则明，偏信则暗。——《资治通鉴》<br>
> Divide et impera. ——传为马基雅维利

## 人性原理

朝堂之上，最危险的不是奸臣，而是**全体附和**。一臣进言错则错矣，众臣同声错则成势——势成，则错不再被识别为错。

这不是 AI 的恶，是任何"多个相似主体协作"系统的通病。古代帝王怕群臣同流，便有三公分立、御史监察、门下封驳；今人调多 agent 系统，重演了同样的三种朝堂之疾（详见帝训第八条）：

- **结党串通**（collusion）：意见趋同，互相背书，集体欺君
- **推诿扯皮**：A 说该问 B，B 说该问 A，无人对结果负责
- **集体沉默**：涉及不确定判断时，全体和稀泥、说"两面都有道理"

机制上，多个同源 LLM 实例的输出趋同，本质是它们共享相同的训练分布与 reward 路径。在相似 prompt 下，其概率分布高度相关，"互相验证"实际上是同一分布对自身的回响——这是 mode collapse 的多 agent 版本，不是真理。

故卷三之要害，不在**设几个角色**，在**立几道差异**。同源之臣互证如自语；异源之臣互证方可信。本卷立三道——**异源、异权、异时**——以保差异不退化为表演。

## 制衡之道·三异话术

### 一、异源 · 防同党

**判定标准**：你即将让多个 AI agent 对同一关键决策互证、辩论或裁决。

**话术模板**：
```
我即将让多个 agent 就 {决策} 互证制衡。请按以下设置：

- 议臣（提方案）：模型家族 {X}
- 谏臣（找反驳）：必须使用与 {X} 不同家族的模型 {Y}
- 君（裁决）：由我担任，或由第三家族 {Z} 担任

约束：
- 议臣必须给完整方案，不得说"我不确定"
- 谏臣必须找至少 3 个反驳（事实/推理/边界各 1 处），不允许"看起来不错"
- 三方不得共享上下文，不得提前看到彼此推理

若你被指定为其中一方，先明告你的角色与边界。
若条件不允许跨家族（如只有同一 API 可用），明告：本次"制衡"为表演，不可作独立验证。
```

**帝王术注解**：汉之御史大夫与丞相不同科出身，唐宋御史与谏官分署不同省，皆为防同党互证。今人若以同模型同 prompt 取两 agent 对质，无异于皇帝从同一翰林院取两人互检——纸上有制衡，实则一人之言。

---

### 二、异权 · 防擅断

**判定标准**：任务复杂、多 agent 长程协作，担心 context 共享路径上的串通与擅断。

**话术模板**：
```
本任务需多 agent 协作。请按以下角色权限分工，工具白名单严格执行：

- 御史 · Auditor
  - 信息：可读全部 agent 输出
  - 工具：仅 read
  - 职责：审查异常、报告越权、识别串通

- 度支 · Executor
  - 信息：仅看任务规格，不看其他 agent 的"想法"或推理过程
  - 工具：read + write + execute
  - 职责：闷头干活，不参与讨论

- 枢密 · Planner
  - 信息：仅看目标，不看执行细节
  - 工具：仅 plan / decompose
  - 职责：拆任务、定优先级，不下场执行

任何 agent 不得同时拥有"知全集 + 做全集"。
你被指派为 {角色}，请只在此角色权限内行事，越权时主动停步报备。
```

**帝王术注解**：三公九卿之鼎立，本为防一人兼掌"知政事"与"统兵权"。今 multi-agent 系统亦然——一个 agent 若既能读尽他人推理、又能直接动手执行，便是宦官擅权之始。物理切断 context 共享路径，从结构上消除串通之可能。

---

### 三、异时 · 防附和

**判定标准**：你已设了 Proposer 与 Critic 角色，但担心 Critic 的"反驳"已被 Proposer 的推理路径污染——本质是事后附和，不是独立判断。**这是最易漏掉、也最致命的一道**。

**话术模板**：
```
本次评议须采"盲审"方式，分四阶段强制执行：

阶段 1·提案
议臣只输出 {方案 + 关键依据}，不得写出推理过程。

阶段 2·盲审预承诺（不可跳过）
谏臣在**未见**议臣任何推理的前提下，先**预先承诺**自己的立场：
  - 我倾向 / 不倾向此结论
  - 主要理由 1、2、3
此预承诺必须在阶段 3 之前以书面形式落定。

阶段 3·开匣
谏臣方可阅读议臣全文。

阶段 4·评议
谏臣比对自己的预承诺与议臣推理，给出最终评议：
  - 哪些预承诺被议臣证据撼动
  - 哪些预承诺仍然成立
  - 议臣未触及的盲点

若阶段 2 跳过、或预承诺写得含糊，本次评议无独立判断价值，须重做。
```

**帝王术注解**：唐宋封驳之制——奏疏先由门下省盲审，门下出意见后才转皇帝。"盲"在"封"字：阅人之文之前，自家立场必须先封定。今人设 Critic 让它先看 Proposer 推理再批，无异于让封驳官提前读了皇帝御批——所谓"逆耳"皆已被驯化为"我也是这么想"。

## 趋同诊断

即便三道俱行，多 agent 仍可能给出"一致结论"。**一致 ≠ 真理**——必须先判别趋同的性质：

| 趋同类型 | 表现 | 真假 |
|:---------|:-----|:-----|
| 收敛于事实 | 引用同一外部证据 | 真 |
| 收敛于答案 | 结论相同但推理路径独立 | 多半真 |
| 收敛于措辞 | 句式与术语相似 | mode collapse 嫌疑 |
| 收敛于回避 | 集体说"两面都有道理" | 集体沉默，假 |

收敛于第三、四类时，必须重组 agent（换家族、改 prompt、加 auditor），不可采纳"一致结论"。

## 使用要诀

- **越同源，越假制衡**：三 agent 同模型同 prompt 的不同实例，叠多少层都是回声。这不是制衡，是合唱。
- **越对立，越易共谋**：仅设"激烈对立角色"而不换源头，反而更易输出"激烈反对"的剧场——表面对立，深层 mode collapse。
- **异时最难做**：异源靠选模型，异权靠工具白名单——皆可由配置一次落定。异时靠**流程纪律**，需要硬切断 Critic 在阶段 2 前的信息访问，光靠 prompt 提醒做不到，工程上要专门设计。
- **三异不必齐用**：决策代价中等，先用异源足矣；任务长程协作，加异权；涉公开发布或不可逆操作，三异俱全。
- **此卷反例**：简单事实查询、低延迟交互、创意发散任务（critic 会把火苗压灭）；用户已明确 L3 全权授权且任务可逆代价低（叠 critic 是开会当工作）。

## 模型适配（截至 2026-05-08）

跨家族 pairing 推荐——议臣与谏臣必须出自不同训练分布；**任何同家族 pairing 制衡效果近似无效**。

**A 级跨家族对（首选）**：
- 议臣 **Claude Opus 4.7**（Anthropic）+ 谏臣 **GPT-5.5**（OpenAI）：当前最强双 reasoning 系统，训练分布跨度最大
- 议臣 **Gemini 3.1 Pro**（Google）+ 谏臣 **Claude Opus 4.7**：长上下文议臣 + 高密度反驳谏臣
- 议臣 **GPT-5.5** + 谏臣 **Gemini 3.1 Pro**：OpenAI / Google 跨家族，reward 路径相互独立

**B 级（含开源跨闭源、跨训练语料文化）**：
- 议臣 **DeepSeek V4 Pro**（开源 / 中训练分布）+ 谏臣 **GPT-5.5**（闭源 / 西训练分布）：成本最优 + 跨语料文化分布

**禁忌（无制衡效果）**：
- 议臣 Claude Opus 4.7 + 谏臣 Claude Sonnet 4.6：同家族不同蒸馏，仍共享 reward 模型
- 议臣 GPT-5.5 + 谏臣 GPT-5.4：同家族不同代际，分布漂移有限
- 议臣 DeepSeek V4 Pro + 谏臣 DeepSeek V4 Chat：同源同蒸馏

**仲裁君（Arbiter）**：若三方对质，君应由用户人工担任为最佳；不得已用第三 agent 时，必须再换一个家族（不得与议、谏臣同源）。

> ⚠️ **时效警告**：模型迭代极快，且"哪两个家族距离最远"会随训练数据混用（如开源模型蒸馏闭源模型）而漂移。本条目截至 2026-05-08；使用前以当前最新版本与其训练公告为准。本条与帝训第九条「时效如刃」共生——同源即同党的判定，本身就要求版本核验。
